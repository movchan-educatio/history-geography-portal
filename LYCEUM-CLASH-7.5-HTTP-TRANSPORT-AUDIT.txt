LYCEUM CLASH 7.5 — HTTP TRANSPORT

ЗНАЙДЕНО ДВІ ПРОБЛЕМИ.

1. Створення кімнати у 7.4 все ще робило:
await set(roomRef,payload)
через Firebase Realtime SDK.
Якщо websocket/long-poll Firebase не підтверджує write, Promise може залишатися pending — саме це виглядає як нескінченне «СТВОРЮЮ…».

2. У 7.4 були виклики bellClashForceRoomSync() і bellClashStopJoinSync(), але їхніх визначень у файлі вже не було.
Це могло ламати Join/Start/Leave після створення кімнати.

ЩО ЗРОБЛЕНО

• Create Room переведено на Firebase REST API через звичайний HTTPS PUT.
• Використовується Firebase ID token поточного Google-користувача.
• HTTP має чітку відповідь або timeout — нескінченного очікування немає.
• Join працює через REST + ETag conditional transaction.
• Start Room також працює через ETag transaction.
• Map/Bot settings переведені на REST transaction.
• Room watcher тепер подвійний:
  - SDK onValue;
  - незалежний HTTPS GET кожні 850 мс.
• Player movement при здоровому SDK пишеться як раніше.
• Якщо SDK disconnected — позиції йдуть через throttled HTTPS PATCH.
• bellClashForceRoomSync(), bellClashStopJoinSync(), bellClashStartJoinSync() відновлені.
• На екрані видно транспорт:
  🌐 SDK realtime
  або
  🌐 HTTPS fallback

ЯКЩО FIREBASE RULES БЛОКУЮТЬ ЗАПИС
HTTPS REST поверне 401/403, і гра покаже ROOM_PERMISSION.
Це вже буде точний доказ проблеми rules, а не «зависання».
