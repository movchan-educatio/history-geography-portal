LYCEUM CLASH 7.0 — JOIN SYNC FIX

ПРОБЛЕМА З ФОТО
На двох пристроях видно одну кімнату NAR5Y.
HOST уже перейшов у матч, але пристрій, який приєднався за кодом, міг залишитися в lobby.

ГОЛОВНА ПРИЧИНА В КОДІ
Попередня логіка запускала bellClashEnterMatch() тільки коли локально було зафіксовано саме ПЕРЕХІД:
previousStatus !== 'playing' -> room.status === 'playing'.

Якщо клієнт:
• підписався трохи пізніше;
• отримав reconnect;
• пропустив один realtime callback;
• уже мав локальний snapshot зі status='playing';
то умова могла більше не виконатися.
У результаті Firebase-кімната вже грала, а UI приєднаного пристрою залишався в lobby.

ЩО ЗМІНЕНО

1. НОВЕ ПРАВИЛО ВХОДУ
Якщо:
• room.status === 'playing';
• поточний uid реально є в room.players;
• bellClash.running === false;
то клієнт ЗАВЖДИ переходить у матч.
Попередній previousStatus більше не потрібен для входу.

2. ОКРЕМИЙ STATUS LISTENER
Крім загального watcher кімнати є окрема realtime-підписка на:
/lyceumClashRooms/CODE/status

Навіть якщо рендер lobby або інший callback дасть помилку, PLAYING-подія все одно запускає force sync.

3. JOIN POLLING FALLBACK
Після приєднання раз на 650 мс перевіряється поточний room snapshot, поки матч не почався.
Це страховка на reconnect / пропущений websocket event.
Після успішного входу polling вимикається.

4. FORCE ROOM SYNC
bellClashForceRoomSync():
• читає актуальну кімнату;
• відновлює players/bots/map;
• знаходить саме поточного joined player;
• переносить його slot/hero/skin/weapon у local state;
• якщо status='playing' — запускає матч.

5. ENTER MATCH СТАВ IDEMPOTENT
bellClashEnterMatch():
• не запускається двічі;
• перевіряє, що room status справді playing;
• перевіряє, що поточний uid присутній у room.players;
• бере spawn саме з mine.slot, а не зі старого local.slot.

6. HOST START
Після успішного StartRoom HOST теж робить force sync.
Тобто і host, і joined clients використовують один механізм переходу.

7. ВЕРСІЯ КІМНАТИ
Нові кімнати мають:
protocol='clash-7.0'
schema=4

У lobby поруч із КІМНАТА видно v7.0.
Це дозволяє легко перевірити, що обидва пристрої реально оновили сторінку і не тримають старий JS у відкритій вкладці.

8. ПЕРЕВІРКА
• portal-score.js — node --check OK.
• Усі inline JavaScript-блоки index.html — node --check OK.
• Старої умови previousStatus !== 'playing' для входу в матч більше немає.
